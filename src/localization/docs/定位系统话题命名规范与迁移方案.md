# 定位系统话题命名规范与迁移方案

> 版本：v1.1（实施稿，已落地）
> 日期：2026-10-12
> 范围：localization 全系统（里程计族 / 定位融合 / 全局匹配 / 重定位）的输入输出话题统一
> 状态：**已实施完成**（一次性切换，38 文件 + 重定位相对名归域）；D1~D7 已确认，见 §7。

---

## 1. 目标与命名规则

需求转成的规则：

1. **二级表达**：`/模块/子话题`——从话题名即可看出所属模块；
2. **同功能不同实现 → 模块名区分、子话题名一致**：如各版本里程计都输出 `/slam_odometry/odom`（实现版本不进话题名，用节点名/参数区分）；
3. **模块归属即命名空间**：里程计 `/slam_odometry|dr_odometry/`、定位 `/localization/`、全局匹配 `/global_matcher/`、重定位 `/pc_reloc|v_reloc/`；
4. **传感器输入不改**：`/ouster/*`、`/can_receive_info`、`/gnss_chc_data` 属传感器域，保持原生名；
5. **系统惯例话题不改**：`/initialpose`（RViz 2D Pose Estimate 默认）、`/tf`、`/clock`、`/rosout`。

## 2. 现状盘点

### 2.1 各模块现有话题

| 模块 | 方向 | 现有话题 | 问题 |
|---|---|---|---|
| **slam_odometry_v2** | 出 | `/localization/slam_odom`、`/localization/cloud_registered`、`/localization/cloud_registered_effect`、`/localization/local_map` | 占用 `/localization/` 前缀，看不出是里程计 |
| **lio_odometry / _v2**（及 plus/Voxlmap/bievr） | 出 | `/slam_odometry/odom`、`/slam_odometry/cloud_registered`、`/slam_odometry/cloud_effect` | ✅ 已符合目标（部分族已统一） |
| **dr_odometry_v2** | 出 | `/localization/dr_odom`、`/localization/dr_status`、`/localization/dr_path`、`/localization/dr_odometry_v2/global_map` | 混入 `/localization/`；global_map 还是三级名 |
| **source_bridge** | 出 | `/localization/odom_source`、`/localization/source_cloud` | 归属待定（定位链路内部件） |
| **localization_v3（fusion）** | 出 | `/localization_v2/odom`、`/localization_v2/map_to_odom`、`/localization_v2/status`、`/localization_v2/path`、`/localization_v2/gm_anchor`、`/localization_v2/loc_point`、`/localization_v2/current_scan_in_map` | **带版本号** `/localization_v2/`——版本进话题名是主要乱象来源 |
| **global_matcher_v2** | 出 | `/localization/global_matcher/result`、`.../status`、`.../global_map`、`.../aligned_scan`、`.../target_submap` 等 11 个 | 三级名且占 `/localization/` |
| **relocalization（pc）** | 出 | `/reloc_pose`、`/reloc_status`、`/reloc_aligned_scan`、`/reloc_target_submap`（相对名→根命名空间）+ `/localization/relocalization/result` | **无模块前缀**（散落在根下）+ 结果话题三级名 |
| **aruco_relocalization（v）** | 出 | 同上（共用 result 话题） | 同上 |
| 系统惯例 | — | `/initialpose`、`/tf` | 保持 |

### 2.2 模块间连线（现状）

```
传感器(/ouster,/can,/gnss) ──► slam_odometry_v2 ──/localization/slam_odom──┐
                             dr_odometry_v2 ────/localization/dr_odom─────┤
                             source_bridge ◄──────────────────────────────┘
                                  │ /localization/odom_source + /localization/source_cloud
                                  ▼
                             localization_v3 ──/localization_v2/*──► 下游
                                  ▲                      │
             /localization/global_matcher/result ────────┤ gm_anchor 反馈
             /localization/relocalization/result ────────┘
```

### 2.3 ⚠️ 半迁移断点（先修）

| 断点 | 现象 |
|---|---|
| **GM 跟踪初值断线** | `global_matcher_v2.yaml: initial_pose: /localization/fused_odom`，而 fusion 实发 `/localization_v2/odom` → **GM 拿不到跟踪初值**（一直走 bootstrap） |
| GM 部分源话题已改 | `source_odom: /slam_odometry/odom`、`source_cloud: /slam_odometry/cloud_registered`（=lio 族的输出名）——与 slam_odometry_v2 实发名不一致 |

结论：命名迁移不是"纯重构"，**当前配置间已互相不匹配**，本次统一应一并修好。


## 5. 修改点清单（✅ 已实施）

| # | 位置 | 内容 |
|---|---|---|
| 1 | 各模块 `config/*.yaml` topics 段 | 按映射表改值（slam_odometry_v2 / dr_odometry_v2 / localization_v3 / source_bridge / global_matcher_v2 / relocalization / aruco） |
| 2 | `localization_v3.launch` | 删除散落的 `<param name="topics/...">` 覆盖（GM/bridge/fusion 的接线统一进各自 yaml），只留"选哪个源"的开关；启动 dr/bridge 的 include 保持 |
| 3 | 旧版本模块（lio 族、global_matcher v1、localization_manager 等） | 同规则套用（lio 族已合规仅微调；v1 系列按映射改） |
| 4 | rviz 配置（`localization_v3/rviz/*.rviz`） | 显示话题改新名 |
| 5 | **下游**：planning 订阅 `/localization/loc_point` | 需同步（本次唯一外部消费者） |
| 6 | 文档 | 各 README/设计文档的话题图更新；本文档成为规范基线 |

## 6. 迁移步骤建议

1. **S1 修断点**（优先）：把 GM `initial_pose` 与 fusion 输出对齐（先修半迁移的断线）；
2. **S2 定名确认**：敲定 §7 决策点；
3. **S3 分域实施**：里程计域 → 定位域 → GM 域 → 重定位域（每域一次编译+启动冒烟）；
4. **S4 下游同步**：planning/rviz/脚本；
5. **S5 回归**：完整链路 bag 跑一段（复用现有验证脚本），确认无 "topic not found" 级问题。
