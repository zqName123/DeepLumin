## 1. 头文件保护宏（Include Guard）

### 代码示例

```cpp
// constants.h
#ifndef AUTOWARE_HEALTH_CHECKER_CONSTANTS_H
#define AUTOWARE_HEALTH_CHECKER_CONSTANTS_H

// ... 声明内容 ...

#endif  // AUTOWARE_HEALTH_CHECKER_CONSTANTS_H
```

### 这是什么？

**问题**：如果一个头文件被 `#include` 了两次，编译器会报"重复定义"错误。

**解决方案**：用一个**独特的宏名字**把声明包起来。第一次 `#include` 时宏不存在，进入 `#ifndef` 块并定义宏；第二次 `#include` 时宏已经存在，直接跳过。

### 宏命名规范

格式：`项目名_文件名_H`

```
AUTOWARE_HEALTH_CHECKER_CONSTANTS_H
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  包名              文件名
```

### C++11 替代方案：`#pragma once`

现代 C++ 也可以写：
```cpp
#pragma once
// ... 声明内容 ...
```

更简洁，但不是标准 C++（是编译器扩展，几乎所有编译器都支持）。这份代码里用的是传统宏方式。

## 2. 命名空间 namespace

### 代码示例

```cpp
namespace autoware_health_checker
{
  using ErrorLevel = uint8_t;
  using ErrorKey = std::string;
  // ... 类声明
}  // namespace autoware_health_checker
```

### 这是什么？

命名空间就是给代码**套一个"域名"**，防止名字冲突。就像网站里 `github.com` 和 `google.com` 都可能有 `index.html`，但不会冲突。

### 实际使用

```cpp
// 写在头文件里：用 autoware_health_checker::HealthChecker
// 或写 using 声明简化
using autoware_health_checker::HealthChecker;

// 或在 .cpp 文件里整个 using namespace
using namespace autoware_health_checker;
// 之后直接写 HealthChecker、ErrorKey 等
```

### 为什么 .cpp 文件里又套了一层 namespace？

```cpp
// health_checker.cpp
namespace autoware_health_checker
{
HealthChecker::HealthChecker(...) { ... }
ErrorLevel HealthChecker::CHECK_MIN_VALUE(...) { ... }
}  // namespace autoware_health_checker
```

这是**在命名空间里定义成员函数**。头文件里写了类声明（属于 namespace），源文件里就必须也在同一个 namespace 里给出实现。

## 3. 类型别名 using（C++11 起）

### 代码示例

```cpp
// constants.h
using ErrorLevel = uint8_t;
using ErrorKey = std::string;
using MinMax = std::pair<double, double>;
```

### 这是什么？

给类型起个别名，让代码**可读、好维护**。

### 和老式 typedef 的区别

```cpp
// C++98 写法
typedef uint8_t ErrorLevel;

// C++11 写法
using ErrorLevel = uint8_t;
```

两者功能相同，但 `using` 更直观（像赋值），而且 `using` 可以用于模板别名（`typedef` 不行）。

### 这份代码里还用 using 简化了消息类型

```cpp
// health_checker.h
using AwDiagStatus = deeplumin_msgs::DiagnosticStatus;

```

这样写 `AwDiagStatus::FATAL` 比写 `deeplumin_msgs::DiagnosticStatus::FATAL` 方便多了。

## 4. constexpr（C++11）

### 代码示例

```cpp
constexpr double BUFFER_DURATION = 0.5;
constexpr double NODE_STATUS_UPDATE_RATE = 10.0;
```

### 这是什么？

`constexpr` = **const + expression**，表示这个值在**编译时就可以确定**，编译器可以把它当作"字面常量"处理。

### 和 const 的区别

```cpp
const int a = 5;          // const 也表示不可变，但可能是运行时确定
constexpr int b = 10;     // 强制编译时确定

const int c = get_value();  // 合法（如果 get_value 是 constexpr 函数）
constexpr int d = get_value(); // 只有 get_value() 也是 constexpr 才合法
```

在这份代码里，这三个常量都是简单的字面量，用 `constexpr` 告诉编译器可以把它们内联（直接替换数字），没有运行时开销。

## 5. 类与构造函数初始化列表

### 代码示例

```cpp
class HealthChecker
{
public:
  HealthChecker(ros::NodeHandle nh, ros::NodeHandle pnh);
  ~HealthChecker();
  
private:
  ros::NodeHandle nh_;
  ros::NodeHandle pnh_;
  std::thread node_status_publish_thread_;
  bool node_activated_;
  std::atomic<bool> is_shutdown_;
  std::mutex mtx_;
};

// 构造函数的初始化列表
HealthChecker::HealthChecker(ros::NodeHandle nh, ros::NodeHandle pnh)
  : value_manager_(nh, pnh)     // 先初始化成员对象
  , node_activated_(false)      // 简单类型赋值
  , nh_(nh)
  , pnh_(pnh)
  , is_shutdown_(false)
{
  status_pub_ = nh_.advertise(...);   // 函数体内部做的事
}
```

### 这是什么？

初始化列表是构造函数参数列表后、`{}` 函数体前的 `: xxx(yyy), zzz(zzz)` 部分。

### 为什么要用？

```cpp
// ❌ 不好的写法：在函数体内赋值
HealthChecker::HealthChecker(...)
{
  nh_ = nh;              // 先默认构造，再赋值 → 多一次拷贝
  pnh_ = pnh;
  is_shutdown_ = false;
}

// ✅ 好的写法：用初始化列表
HealthChecker::HealthChecker(...)
  : nh_(nh), pnh_(pnh), is_shutdown_(false)
{ }
```

**关键原因**：
1. **效率**：避免先默认构造再赋值
2. **必须**：`const` 成员、引用成员、没有默认构造函数的成员，**只能**在初始化列表里初始化

### 初始化列表和成员声明顺序

初始化列表的执行顺序**不是**按你写的顺序，而是按**成员变量在类中声明的顺序**。所以最好让两者一致，避免隐藏 bug。

## 6. const 成员函数

### 代码示例

```cpp
class DiagBuffer {
public:
  ErrorLevel getErrorLevel();     // 普通函数，可以修改成员变量
  const ErrorType type;           // const 成员变量（不能修改）
  
private:
  std::vector<ErrorKey> getKeys();     // 普通
  bool keyExist(const ErrorKey& key) const;  // const 函数！
};

bool HealthChecker::keyExist(const ErrorKey& key) const
{
  return (diag_buffers_.count(key) != 0);
}
```

### 这是什么？

在函数签名末尾加 `const`，表示这个函数**承诺不修改任何成员变量**（除了 `mutable` 修饰的）。

### 为什么用？

```cpp
// 好处 1：语义清晰。一看就知道这个函数只读数据。
// 好处 2：const 对象只能调用 const 成员函数。

void example() {
  const HealthChecker checker(...);
  checker.keyExist("test");   // ✅ 可以调用 const 函数
  checker.ENABLE();           // ❌ ENABLE() 不是 const 函数，编译报错
}
```

## 7. 引用 &（Reference）

### 代码示例

```cpp
ErrorLevel CHECK_MIN_VALUE(const ErrorKey& key, const double value, ...)
                          ^^^^                   ^^^^
                          引用参数，避免拷贝
```

### 这是什么？

引用是一个变量的**别名**。`const ErrorKey& key` 可以读作"key 是一个 ErrorKey 的常量引用"。

### 为什么不用值传递？

```cpp
// ❌ 值传递：整个字符串被复制一遍（对 std::string 开销不小）
void foo(ErrorKey key);

// ✅ const 引用：不复制，且不会被修改
void foo(const ErrorKey& key);

// ✅ 非 const 引用：不复制，但函数可以修改原值
void bar(ErrorKey& key);
```

### 规则

| 类型 | 传参方式 | 说明 |
|------|---------|------|
| 基本类型 (int, double, bool) | 值传递 | 拷贝开销极小 |
| 小对象 (std::pair, struct) | 值传递或 const 引用 | 看情况 |
| 大对象 (std::string, std::vector, ROS 消息) | **必须 const 引用** | 避免昂贵拷贝 |

## 8. auto 关键字（C++11）

### 代码示例

```cpp
auto result = std::find_if(node_status_array.begin(), node_status_array.end(), identify);
auto prev_time = std::chrono::system_clock::now();
auto until_time = prev_time + std::chrono::microseconds(loop_usec);
const auto& node_timer = timeout_manager.second;
auto vertex = getTargetNode(node);
```

### 这是什么？

让编译器**自动推断**变量的类型，不用你手写。

### 例子

```cpp
// 不用 auto
std::vector<ErrorKey>::iterator it = vec.begin();
std::chrono::system_clock::time_point t = std::chrono::system_clock::now();

// 用 auto
auto it = vec.begin();
auto t = std::chrono::system_clock::now();
```

### 和 const / 引用组合

```cpp
auto x = 5;            // x 是 int
auto& y = x;           // y 是 int&（引用）
const auto& z = y;     // z 是 const int&
auto* p = &x;          // p 是 int*
```

### 注意

```cpp
auto str = "hello";    // ❌ 会推断成 const char*，不是 std::string
auto str2 = std::string("hello");  // ✅ 这样才是 std::string
```

## 9. lambda 表达式（C++11）⭐ 最重要的新特性

### 代码示例

```cpp
// 例子 1：简单的判断函数
auto identify = [&status](const ErrorLevel target_level)
{
  return (status.level == target_level);
};

// 例子 2：带返回值的判断
auto identify = [key, value, thresh_type, this](ErrorLevel level)
{
  return (value < value_manager_.getValue(key, thresh_type, level).get());
};

// 例子 3：用于 std::find_if
auto identify = [&node_status](const NodeStatus& status)
{
  return status.node_name == node_status.node_name;
};
auto result = std::find_if(array.begin(), array.end(), identify);

// 例子 4：三元 lambda
auto isOverWarn = [](ErrorLevel level)
{
  return (level == WARN || level == ERROR || level == FATAL);
};
```

### 这是什么？

lambda 表达式就是**内联的匿名函数**。你不需要单独写一个命名函数，直接在需要的地方写。

### 语法拆解

```cpp
[capture](parameters) -> return_type { body }
^^^^^^^^  ^^^^^^^^^^   ^^^^^^^^^^   ^^^^^
 捕获      参数列表      返回类型    函数体    ← 返回类型可以省略（自动推断）
```

### 捕获列表详解（最关键的部分）

```cpp
int x = 10;
int y = 20;

[=]() { ... }     // 值捕获：lambda 内部获得 x 和 y 的拷贝
[&]() { ... }     // 引用捕获：lambda 内部直接用外面的 x 和 y（可能修改）
[=, &y]() { ... } // 混合：x 是值，y 是引用
[&, x]() { ... }  // 混合：y 是引用，x 是值
[x, &y]() { ... } // 指定：x 值捕获，y 引用捕获
[this]() { ... }  // 捕获当前对象的 this 指针（lambda 里可以访问成员变量）
```

### 这份代码里最重要的一个

```cpp
auto identify = [key, value, thresh_type, this](ErrorLevel level)
{
  return (value < value_manager_.getValue(key, thresh_type, level).get());
};
```

- `key`, `value`, `thresh_type` — 值捕获（把外面的局部变量**拷贝**进 lambda）
- `this` — 捕获当前对象的指针，这样 lambda 内部可以访问 `this->value_manager_`

### 为什么要用 lambda？

**如果不用 lambda**：你需要：
1. 在类外定义一个全局函数，或者
2. 定义一个函数对象类，或者
3. 定义一个静态成员函数

每种都比写 lambda 更啰嗦。Lambda 的设计初衷就是"写小函数不麻烦"。

## 10. std::unique_ptr — 独占智能指针（C++11）

### 代码示例

```cpp
std::map<ErrorKey, std::unique_ptr<DiagBuffer>> diag_buffers_;

// 创建
diag_buffers_[key] = std::make_unique<DiagBuffer>(key, type, desc, duration);

// 使用
diag_buffers_.at(key)->addDiag(status);
```

### 这是什么？

`unique_ptr` 是一个**自动管理内存的指针**，它保证**一个对象同时只有一个 unique_ptr 拥有它**。当 unique_ptr 被销毁时（比如超出作用域，或者 map 被 clear），它指向的对象**自动 delete**。

### 和裸指针的对比

```cpp
// ❌ 裸指针：需要手动 delete，容易忘记或重复 delete
DiagBuffer* buf = new DiagBuffer(...);
// ... 使用 buf ...
delete buf;   // 忘了这行就是内存泄漏

// ✅ unique_ptr：自动管理
auto buf = std::make_unique<DiagBuffer>(...);
// ... 使用 buf ...
// 不用管 delete，buf 超出作用域自动释放
```

### 为什么是 unique 而不是 shared？

```cpp
std::unique_ptr<T>  // 独占：只有一个拥有者。开销小。
std::shared_ptr<T>  // 共享：多个拥有者，引用计数。开销略大。
std::weak_ptr<T>    // 弱引用：不增加引用计数，配合 shared_ptr 用。
```

在这份代码里，每个 DiagBuffer 只在 `diag_buffers_` map 里有一个拥有者，所以用 unique_ptr 就够了。

### make_unique vs new

```cpp
// ❌ 不好
unique_ptr<T> p(new T(args...));

// ✅ 好
auto p = std::make_unique<T>(args...);
```

`make_unique` 更安全（避免 `new` 和 `delete` 分离），且代码更简洁。

## 11. std::mutex + std::lock_guard — 线程互斥锁

### 代码示例

```cpp
void DiagBuffer::addDiag(DiagnosticStatus status)
{
  std::lock_guard<std::mutex> lock(mtx_);   // ← 加锁
  buffer_[status.level].status.emplace_back(status);
  updateBuffer();
}   // ← lock 超出作用域自动解锁
```

### 这是什么？

**问题**：两个线程同时写同一个数据 → **竞争条件（Race Condition）** → 数据乱掉。

**解决方案**：在读写共享数据前"上锁"，操作完"解锁"。同一时刻只有一个线程能拿到锁。

### 为什么用 lock_guard 而不是手动 lock/unlock？

```cpp
// ❌ 手动：如果中间抛异常了，unlock 永远不会被调用 → 死锁！
mtx_.lock();
// ... 可能抛异常的代码 ...
mtx_.unlock();

// ✅ lock_guard：构造时自动 lock，析构时自动 unlock（RAII 原则）
{
  std::lock_guard<std::mutex> lock(mtx_);
  // ... 无论是否抛异常，离开作用域都会自动解锁
}
```

RAII = **Resource Acquisition Is Initialization**（资源获取即初始化）。对象构造时获取资源，析构时释放。这是现代 C++ 管理资源的核心原则（也是 unique_ptr 背后的理念）。

## 12. std::atomic — 原子变量（C++11）

### 代码示例

```cpp
std::atomic<bool> is_shutdown_;
// 初始化
, is_shutdown_(false)
// 跨线程读写
is_shutdown_.store(true);       // 写
while (ros::ok() && !is_shutdown_.load()) { ... }  // 读
```

### 这是什么？

`atomic` 让一个变量的读写**成为不可分割的原子操作**。一个线程在读的时候，另一个线程不可能写一半。

### 为什么不用 mutex？

mutex 可以保护几乎任何操作，但**有开销**（需要内核介入）。`atomic<bool>` 的 `store/load` 通常只需要一条 CPU 指令，**效率极高**。

### 什么时候用 mutex，什么时候用 atomic？

| 场景 | 用什么 |
|------|--------|
| 单个简单变量的读写 (bool, int, pointer) | `std::atomic` |
| 多个变量需要一起保护 | `std::mutex` + `lock_guard` |
| 复杂数据结构 (map, vector) | `std::mutex` + `lock_guard` |

### 对比

```cpp
// 用 atomic
std::atomic<bool> flag{false};
flag.store(true);
if (flag.load()) { ... }

// 用 mutex（保护单个 bool 也能行，但开销大）
std::mutex mtx;
bool flag = false;
{
  std::lock_guard<std::mutex> lock(mtx);
  flag = true;
}
```

## 13. std::thread — 线程（C++11）

### 代码示例

```cpp
void HealthChecker::ENABLE()
{
  node_status_publish_thread_ = std::thread(&HealthChecker::publishStatus, this);
}

HealthChecker::~HealthChecker()
{
  is_shutdown_.store(true);
  if (node_status_publish_thread_.joinable())
  {
    node_status_publish_thread_.join();
  }
}
```

### 这是什么？

`std::thread` 是 C++ 标准库提供的线程类。`joinable()` 检查线程是否还能被 `join`（比如没 join 过、也没 detach 过），`join()` 阻塞等待线程结束。

### 启动线程的几种方式

```cpp
// 方式 1：普通函数
void func() { ... }
std::thread t1(func);

// 方式 2：lambda
std::thread t2([]() { /* ... */ });

// 方式 3：成员函数（这份代码用的）
// std::thread(&类名::函数名, 对象指针/引用)
std::thread t3(&HealthChecker::publishStatus, this);
```

### 析构函数里的安全退出模式

```cpp
// 1. 先发信号让线程退出循环
is_shutdown_.store(true);

// 2. 等待线程真正结束
if (node_status_publish_thread_.joinable())
{
  node_status_publish_thread_.join();
}

// 3. 线程结束后，node_status_publish_thread_ 的析构函数会自动清理
```

## 14. 范围 for 循环（Range-based for，C++11）

### 代码示例

```cpp
// 遍历 map
for (const auto& checker : rate_checkers_)
{
  keys.emplace_back(checker.first);
}

// 遍历 vector
for (const auto& level : level_array)
{
  buffer_[level] = filterBuffer(now, level);
}

// 遍历固定数组
static const std::array<ErrorLevel, 5> level_array =
  { FATAL, ERROR, WARN, OK, UNDEFINED };
```

### 这是什么？

简洁的遍历语法，自动处理了"从 begin() 到 end()"的细节。

### 和老式 for 的对比

```cpp
// ❌ 老式（C++98）
for (std::map<ErrorKey, RateChecker>::iterator it = rate_checkers_.begin();
     it != rate_checkers_.end(); ++it)
{
  keys.emplace_back(it->first);
}

// ✅ 范围 for（C++11）
for (const auto& checker : rate_checkers_)
{
  keys.emplace_back(checker.first);
}
```

### 循环变量的三种写法

```cpp
std::vector<int> vec{1, 2, 3};

for (auto val : vec) { val = 10; }          // 值拷贝，修改不影响原数据
for (auto& val : vec) { val = 10; }         // 引用，修改影响原数据
for (const auto& val : vec) { /* 只读 */ }   // const 引用，推荐！
```

**推荐用 `const auto&`**：效率最高（不拷贝）、语义清晰（只读）。

## 15. std::map — 哈希映射表

### 代码示例

```cpp
std::map<ErrorKey, std::unique_ptr<DiagBuffer>> diag_buffers_;
std::map<ErrorKey, std::unique_ptr<RateChecker>> rate_checkers_;

// 插入
diag_buffers_[key] = std::make_unique<DiagBuffer>(...);

// 访问
diag_buffers_.at(key)->addDiag(status);

// 检查是否存在
diag_buffers_.count(key) != 0    // count 返回 0 或 1（因为 key 唯一）
```

### 这是什么？

`std::map` 是**按键排序**的键值对容器。查找、插入、删除都是 O(log n)。

### `[]` vs `.at()` 的区别

```cpp
// 如果 key 不存在：
diag_buffers_[key]       // ✅ 自动创建一个默认值（unique_ptr 默认是空指针）
diag_buffers_.at(key)    // ❌ 抛出 std::out_of_range 异常
```

### 注意：std::map 和 std::unordered_map 的区别

```
std::map             → 红黑树，按 key 排序，O(log n) 查找
std::unordered_map   → 哈希表，不排序，平均 O(1) 查找
```

这份代码用了 `std::map`，可能是为了在调试时输出有序的结果。如果不需要排序，`unordered_map` 效率更高。

## 16. std::vector — 动态数组

### 代码示例

```cpp

keys.emplace_back(buf.first);          // C++11，直接在 vector 里构造
keys.push_back(buf.first);             // 传统写法，先构造再拷贝/移动
status.insert(status.end(),            // 从另一个 vector 批量追加
```

## 18. std::find_if + std::sort + std::bind — 算法组合

### 代码示例 1：std::find_if

```cpp
auto identify = [&node_status](const NodeStatus& status)
{
  return status.node_name == node_status.node_name;
};
auto result = std::find_if(array.begin(), array.end(), identify);
if (result != array.end())   // 找到了
  *result = node_status;
```

**逻辑**：`find_if` 从区间 `[begin, end)` 中找到**第一个**让 `identify` 返回 true 的元素。没找到就返回 `end()`。

### 代码示例 2：std::sort + std::bind

```cpp
bool DiagBuffer::isOlderTimestamp(const DiagnosticStatus &a,
    const DiagnosticStatus &b)
{
  return a.header.stamp < b.header.stamp;
}

// 排序！
std::sort(status.begin(), status.end(),
  std::bind(&DiagBuffer::isOlderTimestamp, this,
  std::placeholders::_1, std::placeholders::_2));
```

**这是什么鬼？** 让我拆解：

1. `isOlderTimestamp` 是一个**成员函数**，需要 `this` 指针才能调用。
2. `std::sort` 期望一个普通的**二元函数** `bool f(T a, T b)`。
3. `std::bind` 把成员函数"绑"成一个普通函数：
   - `&DiagBuffer::isOlderTimestamp` — 成员函数指针
   - `this` — 第一个参数（隐式的）
   - `std::placeholders::_1` — 第二个参数的占位符（排序时填入第一个元素）
   - `std::placeholders::_2` — 第三个参数的占位符（排序时填入第二个元素）

**等价理解**：
```cpp
// bind 的效果相当于创建了一个 lambda：
[&](const DiagnosticStatus& a, const DiagnosticStatus& b)
{
  return this->isOlderTimestamp(a, b);
}
```

**C++11 之后**，更推荐直接用 lambda 替代 `std::bind`：
```cpp
std::sort(status.begin(), status.end(),
  [this](const auto& a, const auto& b) {
    return this->isOlderTimestamp(a, b);
  });
```

## 19. boost::optional — 可选值（C++17 有 std::optional）

### 代码示例

```cpp
boost::optional<double> RateChecker::getRate()
{
  if (ros::Time::now() < start_time_ + ros::Duration(buffer_duration_))
  {
    return boost::none;   // ← 表示"没有值"
  }
  double r = data_.size() / buffer_duration_;
  return r;              // ← 返回一个有值的 optional
}

// 调用方
const auto rate = getRate();
if (!rate)                   // 检查是否有值
{
  return boost::none;
}
auto level = (rate.get() < fatal_rate_) ? FATAL : ...;  // 取出值
```

### 这是什么？

有时候一个函数可能**有返回值，也可能没有**。比如 `getRate()` 在冷启动阶段没有足够数据，无法计算频率。

**在没有 optional 时怎么办？**
```cpp
// 方式 1：返回指针，空指针表示没值
double* getRate();

// 方式 2：返回 bool，通过 out 参数传出实际值
bool getRate(double& out);

// 方式 3：返回特殊值（比如 -1）
double getRate();  // 如果返回 -1 表示无效
```

这些方式都不优雅。`optional<T>` 就是为这种场景设计的。

### 基本用法

```cpp
boost::optional<double> opt;

opt = 3.14;     // 赋值
if (opt)        // 或 if (opt.has_value())
{
  double v = opt.get();  // 或 *opt
  // 注意：如果 opt 是空的调用 get() 会抛异常
}

opt = boost::none;  // 清空
```

### 为什么用 boost::optional 而不是 std::optional？

C++17 标准库终于加入了 `std::optional`。但这份代码编译选项是 `-std=c++14`，所以只能用 Boost 的版本。两者 API 几乎一样。

## 20. boost::property_tree — JSON 序列化

### 代码示例

```cpp
std::string valueToJson(const T& value)
{
  std::stringstream ss;
  boost::property_tree::ptree pt;
  pt.put("value", value);
  write_json(ss, pt);
  return ss.str();
}
```

### 这是什么？

**序列化**：把一个内存里的值转成 JSON 字符串存起来或传输。`boost::property_tree` 是 Boost 里的一个**属性树**库，可以处理 JSON、XML、INI 等格式。

### 逐步解读

```cpp
// 1. 创建一个属性树

pt.put("value", 42.5);

// 3. 创建一个字符串流
std::stringstream ss;

// 4. 把属性树写进字符串流（格式化为 JSON）
write_json(ss, pt);

// 5. 取出字符串
std::string json_str = ss.str();
```

## 21. std::function — 类型擦除的可调用对象（C++11）

### 代码示例

```cpp
// SystemStatusSubscriber 里

// HealthChecker::CHECK_VALUE 模板函数里
template <class T>
ErrorLevel CHECK_VALUE(
  const ErrorKey& key, const T& value,
  std::function<ErrorLevel(T value)> check_func,
  std::function<boost::property_tree::ptree(T value)> value_json_func,
  const std::string& description);
```

### 这是什么？

`std::function` 可以**统一存储**各种可调用对象（函数、lambda、函数对象、bind 结果），不管它们的具体类型是什么。

### 例子


**为什么不直接用模板？** 因为模板的函数参数类型必须在编译时确定，但 `std::vector<std::function<...>>` 可以在运行时放入不同类型的可调用对象。

## 23. 继承与成员访问

### 代码示例

```cpp
// ValueManager 继承 ParamManager
class ValueManager : public ParamManager
{
public:
  ValueManager(ros::NodeHandle nh, ros::NodeHandle pnh)
    : ParamManager(nh, pnh) {}   // 先调用基类构造
  
private:
  std::map<ErrorSummary, double> error_details_;  // 自己额外的成员
};
```

### 这是什么？

继承 = 子类自动拥有父类的所有成员（构造/析构除外）。`ValueManager` 可以直接使用 `ParamManager` 的 `getParams()` 方法和 `params_` 成员。

### 继承时构造函数的调用顺序

```cpp
ValueManager(nh, pnh)
  : ParamManager(nh, pnh)   // ✅ 初始化列表里必须先调父类构造
{
  // 然后才是自己的初始化
}
```

### C++ 的访问控制

| 基类成员 | `public` 继承 | `protected` 继承 | `private` 继承 |
|----------|--------------|-----------------|---------------|
| public | 子类也是 public | 子类变成 protected | 子类变成 private |
| protected | 子类也是 protected | 子类也是 protected | 子类变成 private |
| private | 子类**无法访问** | 子类**无法访问** | 子类**无法访问** |

这份代码里 `ParamManager` 的 `nh_`, `pnh_`, `params_` 都是 `private`，但 `ValueManager` 调用的是它们的**公共方法** `getParams()`，这是正确做法。

## 24. 模板函数

### 代码示例

```cpp
template <class T> ErrorLevel CHECK_VALUE(
  const ErrorKey& key, const T& value,
  std::function<ErrorLevel(T value)> check_func,
  std::function<boost::property_tree::ptree(T value)> value_json_func,
  const std::string& description)
```

### 这是什么？

模板 = **泛型编程**。让函数/类可以处理**不同类型的参数**，而不用你为每种类型都写一份。

### 例子

```cpp
template <typename T>
T max(T a, T b) {
  return (a > b) ? a : b;
}

max(3, 5);          // T 是 int
max(3.14, 2.71);    // T 是 double
max("abc", "xyz");  // T 是 const char*（按字典序比较）
```

编译器会在你**实际调用**的时候，为每种类型生成一份具体代码（这叫**模板实例化**）。所以模板的定义通常放在**头文件**里（编译器需要在每个编译单元里看到完整的模板代码才能实例化）。

### 这份代码里的模板

`CHECK_VALUE<T>` 可以接受**任意类型**的值：double、bool、std::string、甚至自定义 struct。调用方需要提供：
- `check_func` — 告诉它怎么判断这个值的严重级别
- `value_json_func` — 告诉它怎么把值转成 JSON

这就是模板 + 函数式编程的威力——**通用且灵活**。

## 25. 静态成员 static

### 代码示例

```cpp
// 在函数内部用 static 变量
ErrorLevel HealthChecker::CHECK_MIN_VALUE(...)
{
  static const ThreshType thresh_type = "min";
  // ...
}
```

### 这是什么？

函数内的 `static` 变量只会**初始化一次**（第一次执行到这行时），之后每次调用都共享同一个。

### 普通局部变量 vs static 局部变量

```cpp
void counter() {
  int x = 0;        // 每次调用都重新初始化为 0
  x++;
  std::cout << x;   // 永远输出 1
}

void counter_static() {
  static int x = 0;  // 只第一次初始化为 0，之后保持原值
  x++;
  std::cout << x;    // 输出 1, 2, 3, ...（持续累加）
}
```

### 这份代码里为什么用 static？

```cpp
static const ThreshType thresh_type = "min";
```

`ThreshType` 是 `std::string`，构造有开销。用 `static` + `const` 让它只构造一次，之后每次调用 `CHECK_MIN_VALUE` 都复用同一个字符串 `"min"`。

### 和 unique_ptr 的区别


## 27. R"()" — 原始字符串字面量（C++11）

### 代码示例

```cpp
// health_aggregator.cpp 中的正则清理
static const std::vector<std::string> delete_strings =
{
  ".*:", ".*/", R"(\(.*\))", R"([\[\]"\\(){}?.*+^$|!#%&'-=~`@;:,<> ])"
};
```

### 这是什么？

普通字符串里的 `\` 需要转义（写成 `\\`），引号也需要转义。但**原始字符串** `R"()"` 里面的内容**全部原样保留**，包括 `\` 和 `"`。

```cpp
// 普通写法（正则表达式地狱）
std::string regex1 = "\\(.*\\)";           // 匹配括号里的任意内容
// 要写 \\ 才能表示一个反斜杠

// 原始字符串写法（清晰）
std::string regex2 = R"(\(.*\))";          // 一模一样的正则，清爽多了
```

## 28. 三元运算符的"俄罗斯套娃"

### 代码示例

```cpp
const ErrorLevel level =
  (rate.get() < fatal_rate_) ? AwDiagStatus::FATAL :
  (rate.get() < error_rate_) ? AwDiagStatus::ERROR :
  (rate.get() < warn_rate_) ? AwDiagStatus::WARN :
  AwDiagStatus::OK;
```

### 这是什么？

`条件 ? 如果真 : 如果假` 是三元运算符。把多个三元运算符串起来就是"三元链"。

### 等价于 if-else

```cpp
ErrorLevel level;
if (rate < fatal_rate_) level = FATAL;
else if (rate < error_rate_) level = ERROR;
else if (rate < warn_rate_) level = WARN;
else level = OK;
```

### 代码里大量用了这个模式

- `CHECK_MIN_VALUE` / `CHECK_MAX_VALUE` 里的严重级别判断
- `ValueManager::getValue` 里的 level_name 翻译
- `HealthAggregator::convertHardwareLevel` 里的 ROS→Autoware 级别映射

### 风格说明

三元链的可读性见仁见智。个人认为**当所有分支都是简单的返回值时**，三元链比 if-else 更紧凑；但如果分支里有复杂逻辑，还是用 if-else 更好。

## 知识点总结：这份代码值得学习的编码习惯

| 习惯 | 说明 |
|------|------|
| **初始化列表优先** | 构造函数一律用 `: xxx(yyy)` 初始化列表 |
| **const 引用传大对象** | 字符串、vector、ROS 消息一律用 `const T&` |
| **优先 make_unique/make_shared** | 比 new/delete 安全 |
| **lock_guard 而不是手动 lock/unlock** | RAII 自动解锁，防死锁 |
| **用 atomic 保护单变量** | 比 mutex 高效 |
| **lambda 替代小函数** | 就地定义，简洁清晰 |
| **emplace_back 替代 push_back** | 避免多余拷贝 |
| **const 成员函数** | 承诺不修改数据的函数都加 const |
| **auto 简化复杂类型** | map 迭代器、时间类型等 |
| **static const std::string** | 避免反复构造相同字符串 |
| **原始字符串 R"()"** | 正则表达式不再写转义地狱 |
